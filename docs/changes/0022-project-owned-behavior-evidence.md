# Opt-in project-owned behavior and honest tier evidence

Decision: docs/decisions/0054-project-owned-behavior-evidence.md

## Context

Industry inputs support inspectable repository truth, incremental delivery and
observed completion; they do not prescribe our fields or prove benefits. The
WisHarness SDK checkout is unavailable here, so this work qualifies neither its
templates nor actual SDK adoption. A controlled actual-self v1 counterexample
removed design scope coverage and still returned planned; the original scope
was restored. Existing v1 receipt tests also accept a design outside scope.

The narrow repair is delivery-flow 0.2.2: opt-in delivery/v2 binds the existing
behavior source, scenario refs, plan bytes and candidate revision, and distinguishes
covered/not_applicable/not_evaluated/blocked. No new executor, Kernel/base release,
gate, dependency, consumer runtime change or automatic applicability judgment.
Source markers are added to the existing SPEC; no duplicate behavior body is made.
